# Core Beliefs

## 一句话定位
该文档定义团队在 Agent-first 改造中的技术信念与决策倾向，减少隐性知识与上下文漂移。

## 核心内容
1. 仓库内可见优先：Agent 看不到的知识等于不存在。
2. 结构化优先：目录和索引是 Agent 的第一认知地图。
3. 单向依赖优先：核心算法层不得反向依赖实验层。
4. 规则可机检优先：口头规范必须落地为脚本或 CI 门禁。
5. 最小破坏优先：重构以文档和约束为主，不改业务行为。
6. 回归可追踪优先：每次规则调整必须在决策日志记录。
7. 显式边界优先：对子依赖和镜像目录做隔离治理。
8. 失败可修复优先：检查报错必须附可操作修复建议。
9. 渐进披露优先：AGENTS.md 只做地图，不做百科。
10. 人机协同优先：涉及架构意图冲突时必须 NEEDS_HUMAN_REVIEW。

## Agent 行为指引
- 你应该先读 `AGENTS.md` 和 `ARCHITECTURE.md` 再动手。
- 你应该在新增文档后立即更新所属 `index.md`。
- 你不应该把实验临时结论写成长期架构规则。
- 你不应该绕过守卫脚本直接提交重大结构变更。
- 你应在规则冲突时给出两种以上备选方案并标注风险。
