# QUALITY SCORE

## 一句话定位
定义主仓统一质量评分模型和最低合格阈值，作为 PR 合并和版本发布的依据。

## 评分维度
| 维度 | 描述 | 权重 | 通过阈值 |
|---|---|---:|---:|
| 架构一致性 | 是否符合依赖方向和分层规则 | 30 | >= 24 |
| 文档完整性 | index 注册、交叉引用、关键文档覆盖 | 20 | >= 16 |
| 可观测性 | 日志字段、指标定义、自验证步骤 | 15 | >= 12 |
| 测试与验证 | 测试可执行性与关键路径验证 | 20 | >= 14 |
| 可维护性 | 命名、边界清晰度、重复度控制 | 15 | >= 11 |

## 总分规则
- 满分 100，最低通过线 80。
- 任一维度低于阈值即判定“不通过”。
- 若触发 P0 技术债，默认降级为“不通过”。

## 评分执行
1. PR 作者自评并附证据链接。
2. 守卫脚本自动校验可机检项。
3. Reviewer 对不可机检项复核并给出结论。

## Agent 行为指引
- 你应该在改动说明中明确影响了哪些评分维度。
- 你应该优先修复阈值未达标维度，而非追求局部高分。
- 你不应该跳过失败维度直接请求合并。
